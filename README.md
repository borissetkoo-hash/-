# Angry Birds — учебная версия

Игра про птиц и свиней на чистом HTML, CSS и JavaScript. Никаких сборщиков,
никаких фреймворков: открыл файл — и всё работает. Физику считает библиотека
Matter.js, она лежит прямо в репозитории.

Код написан как учебник: почти в каждом файле объясняется не только **что**
делает код, но и **почему** сделано именно так, включая разбор ошибок, которые
были допущены и исправлены по ходу работы.

---

## Как запустить

```bash
npm install          # один раз: ставит браузер для автотестов
npm run serve        # запускает локальный сервер
```

Потом открой в браузере `http://127.0.0.1:8123`.

Почему нельзя просто открыть `index.html` двойным кликом: страница, открытая
через `file://`, не имеет права подгружать соседние файлы. Это защита браузера,
чтобы вредная страница не прочитала твой диск. Локальный сервер эту проблему
снимает.

Если Node.js не установлен, сервер можно поднять и так:

```bash
python3 -m http.server 8123
```

```
css/style.css           оформление интерфейса поверх холста

js/vendor/matter.min.js физический движок Matter.js (сторонняя библиотека)

js/config.js            ВСЕ настройки игры: гравитация, материалы, птицы, очки
js/sprites.js           манифест кадров, создаётся скриптом нарезки автоматически
js/assets.js            загрузка кадров и картинок, с запасным вариантом отрисовки
js/physics.js           физический слой: шаг симуляции, урон, взрывы, траектория
js/entities.js          классы Block, Pig, Bird: тело плюс здоровье плюс вид
js/slingshot.js         рогатка: прицеливание, формула выстрела, пунктир
js/effects.js           частицы: обломки, пыль, взрывы, всплывающие очки
js/levels.js            описания уровней (данные, а не код)
js/game.js              игровой цикл, камера, ввод, состояния, интерфейс

tools/check-levels.js   проверка геометрии уровней без запуска браузера
tools/test-game.js      автотест игры в настоящем браузере
tools/slice-sprites.py  нарезка спрайт-листов на кадры

assets/birds/           кадры птиц, по папке на цвет
assets/pigs/            кадры свиней
assets/props/           рогатка, двумя кусками
                        подробности в assets/README.md
```

Главный принцип структуры: **физика, графика и данные разделены**. Движок не
знает, как выглядит свинья. Рисование не знает, как считается урон. Уровни — это
просто списки объектов. Благодаря этому можно заменить спрайты, не трогая
физику, и наоборот.

## Как всё это работает

### Игровой цикл

Шестьдесят раз в секунду повторяется одно и то же:

1. **обновить физику** — Matter.js двигает тела,
2. **разобрать последствия** — что сломалось, что взорвалось,
3. **нарисовать кадр**.

Физика считается фиксированными порциями по 1/60 секунды, даже если кадры идут
неравномерно. Иначе на медленном компьютере птицы летали бы иначе, чем на
быстром. Приём называется fixed timestep, реализован в `physics.js`.

### Выстрел

Вся суть игры — в одной формуле из `slingshot.js`:

```
натяжение = точка_рогатки - точка_пальца
скорость  = натяжение * жёсткость * коэффициент_птицы
```

Вычитание в таком порядке, потому что птица летит в сторону, **противоположную**
натяжению. Длина натяжения обрезается до `maxPull`, иначе можно было бы утащить
мышку за экран и получить бесконечную скорость.

### Урон

Урон считается не от скорости, а от **кинетической энергии удара**:

```
E = 0.5 * m * v²
```

где `v` — относительная скорость сближения двух тел, а `m` — приведённая масса
`(m1 * m2) / (m1 + m2)`. Так пушинка на большой скорости не ломает доску, а
валун на маленькой — ломает. Дальше энергия умножается на хрупкость материала:
один и тот же удар разбивает лёд и едва царапает камень.

### Баланс полёта

Тут важна не каждая константа по отдельности, а то, как они тянут друг друга.

| Хочу | Прямое решение | Побочный эффект |
|---|---|---|
| больше времени на способность | отодвинуть крепость | нужен более сильный выстрел, полёт снова короткий |
| дострелить дальше | усилить рогатку | птица быстрее, времени опять нет |
| и дальше, и дольше | ослабить гравитацию и смягчить рогатку | то, что надо |
| ещё дальше без ускорения | уменьшить сопротивление воздуха | то, что надо |
| выстрел мягче, но чтобы долетало | ослабить рогатку, ослабить гравитацию и придвинуть крепости | три числа меняются вместе |

Дальность полёта примерно `v² / g`, а время примерно `v / g`. Поэтому слабая
гравитация плюс мягкая рогатка дают ту же дальность, но заметно дольше в
воздухе. Именно так и получается неторопливое «парящее» ощущение оригинала.

Текущие числа: при полном натяжении пологий выстрел долетает до крепости за
0.8 секунды, обычный за 1.0, навесной за 1.8. Максимальная дальность 1950
пикселей при дальнем крае уровней 1690-1800, то есть запас 150-260 пикселей.

Значения, которые держат этот баланс и связаны между собой:

| Что | Значение | Где |
|---|---|---|
| сила рогатки | 0.150 | `slingshot.power` |
| гравитация | 0.95 | `world.gravity` |
| сопротивление воздуха | 0.0016 | `world.airFriction` |
| дистанция до крепостей | 40 | `FORT_OFFSET` в `levels.js` |
| прочность свиньи | радиус × 1.4 × 10 | `pig.hpPerRadius` |

Менять их по одному нельзя: ослабишь рогатку — дальние свиньи станут
недосягаемы, усилишь — полёт станет коротким и способности не успеют.

Всё это проверяется автотестом: он перебирает углы прицеливания и следит,
чтобы и времени хватало, и дальние свиньи оставались достижимыми.

### Камера

Масштабов два. Обзорный показывает уровень от рогатки до крепости, чтобы было
видно, куда целиться. Боевой в полтора раза ближе и едет за птицей. Переход
плавный. Так и цель видно при прицеливании, и попадание разглядеть можно.

### Анимация персонажей

Выражение лица птицы зависит от того, что с ней происходит: на рогатке
спокойное, при натянутой резинке нахмуренное, в полёте злое с оскалом, в момент
удара зажмуренное, после приземления помятое. У свиньи по мере потери здоровья
появляются синяки, а под конец вываливается язык. Плюс свиньи моргают, каждая в
свой момент.

Код не знает номеров кадров: он спрашивает роль, например `fly` или стадию
повреждений, а какой кадр за что отвечает, записано в `js/sprites.js`. Поэтому
спрайт-лист можно перенарезать, не трогая игру.

У чёрной птицы роль `ignite` задана не одним кадром, а списком из трёх: она
раскаляется от коричневой до ярко-оранжевой, пока горит фитиль. Взрыв поэтому
не мгновенный. Задержка нужна не для красоты: игрок успевает увидеть, что
именно сейчас взорвётся, и понять свою ошибку, если промазал.

Отдельная деталь, подсмотренная в записи настоящей игры: птица в полёте не
кувыркается, а всегда смотрит туда, куда летит, а на натянутой рогатке
развёрнута назад вдоль резинки. Физике это ничего не стоит, потому что тело
птицы круглое и его поворот на столкновения не влияет. Угол для картинки
считается отдельно от физического.

### Пунктир траектории

Пунктир не рисуется по школьной формуле параболы: он бы слегка расходился с
реальным полётом. Вместо этого заведён второй пустой физический мир, в котором
прокручивается вперёд одно тело-призрак. Получается ровно та траектория, которая
случится на самом деле.

## Как менять игру

Почти всё настраивается в `js/config.js`, код трогать не нужно.

| Хочу | Что править |
|---|---|
| птицы летят дальше | `slingshot.power` или `world.airFriction` (меньше) |
| дольше висят в воздухе | `world.gravity` (меньше) |
| крепости дальше от рогатки | `FORT_OFFSET` в `js/levels.js` |
| свиньи быстрее гибнут под завалом | `damage.crushRate` |
| всё падает быстрее | `world.gravity` |
| лёд стал крепче | `materials.ice.hp` |
| конструкции реже рушатся сами | `damage.minImpactEnergy` (больше) |
| взрыв мощнее | `abilities.bombRadius` и `bombForce` |
| видеть физические контуры | `debug: true` или клавиша `D` |
| поменять кадры анимации | `ROLES` в `tools/slice-sprites.py`, затем перезапустить нарезку |

## Как устроен уровень

Уровень это функция, которая набивает список блоков и свиней, и всё строительство
идёт снизу вверх через «поверхности».

```js
function level4() {
  const out = { blocks: [], pigs: [], terrain: [] };

  // земляной выступ: возвращает свою верхнюю грань как обычную поверхность
  const ground = putPlatform(out, 1425, 720, GY - 80);

  // ставим стойки на выступ, получаем поверхность их верха
  const top = putColumns(out, [1150, 1230], ground, 120, 'ice', 24);

  // свинья на земле между стойками
  putPig(out, 1190, GY, 20);

  // балка ложится на эти стойки, возвращает новую поверхность
  const roof = putBeam(out, 1190, top, 200, 'stone', 26);

  // и уже на неё ставим следующее
  putPig(out, 1190, roof, 18);

  moveAll(out, FORT_OFFSET);          // отодвигаем всю постройку от рогатки
  return { name: '...', theme: 'day', birds: [...],
           blocks: out.blocks, pigs: out.pigs, terrain: out.terrain };
}
```

Смысл в том, что ни одна высота не считается в уме. Каждая функция принимает
поверхность и возвращает новую, лежащую сверху. Это главное, что защищает от
пересечений тел, из-за которых конструкция разваливается сама.

| Помощник | Что делает |
|---|---|
| `putColumns(out, xs, surface, h, material, w)` | ряд стоек |
| `putBeam(out, x, surface, width, material, thickness)` | горизонтальная балка |
| `putBox(out, x, surface, size, material)` | квадратный ящик, например динамит |
| `putPig(out, x, surface, radius, kind)` | свинья, `kind` бывает `king` |
| `putRoof(out, apexX, surface, length, angle, material)` | два ската с упорами |
| `putPlatform(out, x, width, top)` | земляной выступ рельефа |
| `moveAll(out, dx)` | сдвинуть постройку и рельеф целиком |

### Рельеф

Земля не обязана быть плоской. `putPlatform` создаёт земляной выступ, и дальше
на его верхней грани строят теми же помощниками, что и на земле.

Это не украшение. Выступ меняет игру сразу в трёх местах:

- настильный выстрел врезается в торец плато и не долетает, приходится брать
  навесом и терять точность,
- постройка на высоком плато ближе к траектории, чем на низком, то есть высота
  работает как отдельный параметр сложности,
- в провал между плато сваливаются обломки и свиньи, и падение убивает само.

Отдельная проверка в `npm test` следит, чтобы рельеф не сделал уровень
непроходимым. Она нужна потому, что пунктир траектории считается в пустом
мире-двойнике и про выступы ничего не знает: без этой проверки уровень, где
плато закрывает вообще всё, прошёл бы тесты как исправный.

Правила, которые проверяет `npm run check`:

- тела не должны пересекаться в момент старта, даже на три пикселя,
- ничего не должно висеть в воздухе без опоры,
- балка должна лежать хотя бы на двух стойках, иначе она перевернётся.

Правила, которые проверяет `npm test`:

- конструкция стоит неподвижно первые секунды, сама не разваливается,
- до крепости лететь не меньше 950 мс, иначе не успеть нажать способность,
- дальний край уровня достижим выстрелом с запасом не меньше 120 пикселей,
  иначе уровень нельзя пройти.

Новый уровень добавляется в конец списка `LEVELS`. Число уровней нигде не
продублировано: тест спрашивает его у самой игры.

## Проверки

```bash
npm run check    # геометрия уровней, без браузера, мгновенно
npm run serve    # в отдельном терминале: сервер должен быть запущен
npm test         # полный прогон игры в настоящем Chromium
```

Если `npm test` жалуется, что браузер не найден, скачай его командой
`npx playwright install chromium`. Если браузер лежит в нестандартном месте,
путь можно задать явно: `CHROME_PATH=/путь/к/chrome npm test`.

`check-levels.js` ищет две вещи: тела, которые при старте пересекаются, и тела,
висящие в воздухе без опоры. Пересечение даже в три пикселя движок разруливает
резким расталкиванием, и конструкция «взрывается» сама. В первой версии уровней
этот инструмент нашёл 29 таких ошибок.

`test-game.js` открывает игру в браузере, сам подбирает прицел, стреляет и
проверяет двадцать с лишним утверждений: от «нет ошибок в консоли» до «скаты
крыши не съехали за три секунды».
